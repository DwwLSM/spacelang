First five minutes

This walkthrough opens every part of the debugger once, using the program that ships in the editor. Nothing needs to be installed beyond the server you are already running.

1. Write something

Open the OPT_SP editor. The listing starts as four instructions: 

PUSH_INT 2
PUSH_INT 3
OP 1
HALT

OP 1 is addition, so the operand stack ends up holding a single 5. Keep Assembly selected and press Run. The editor accepts three modes: Python, assembly and encoded .sp; the mode picker decides how the text is read.

Switching pages does not lose work. The editor stores the listing, the mode and the open file in sessionStorage, so Run → visualizer → Back to editor returns you to the same text and the same file.

2. Read the trace

The visualizer replays every instruction with its state side by side: the instruction about to run, the operand stack, the call stack, the heap and anything the program printed. Ints, strings, lists and dicts are shown as values, not as opaque references.

Step with the ⏮ / ⏪ / ⏩ / ⏭ buttons, drag the slider, or use the ← and → keys. Autoplay runs the trace hands-free; the speed slider sets the delay between steps.

3. See the encoded form

Open the Studio and write the same program as Python: 

print(2 + 3)

Two more panes fill themselves: the assembly listing the Python frontend emits, and the encoded .sp file in which every token is a run of spaces. That whitespace file is what the language actually ships. Toggle show spaces to render the runs as visible marks, and Copy raw to take the exact bytes away.

4. Change the low level, keep the mirror

Edit the assembly pane: swap OP 1 (add) for OP 2 (subtract). The Python pane turns stale instead of being overwritten, because nothing in the toolchain turns instructions back into Python.

Sync with AI asks a model for a new Python mirror. The answer is compiled locally first and accepted only when it produces the same instructions; otherwise the pane keeps your text and reports why. The encoded .sp is never sent to the model, only the Python and the assembly. Endpoint, model and key live in the settings menu — with no key configured, sync stays disabled and the rest of the page is unaffected.

5. Run it without Python

Two alternatives to the reference interpreter exist:

  • native/spvm, a standalone C++17 virtual machine built with native/build.ps1.
  • A compiler written in SpaceLang itself, which compiles programs to .sp and is documented in SELFHOSTING.md.

Both read the same .sp artifact you just copied out of the Studio, with no CPython in the loop. The debugger itself always uses the Python traced VM: the native VM is faster, but it exposes no tracing hooks, so there would be nothing to step through.
